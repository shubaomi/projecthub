# ProjectHub — 第四轮迭代修复

> 自定义分类 UX 问题分析 + 修复方案 · 2026-05-20

---

## 问题概述

自定义分类功能已实现数据层（创建/删除/分配/持久化），但**用户交互体验存在三个严重问题**，导致功能"不可发现、不可理解、误导用户"。

---

## Issue 1: 首页项目卡片不显示自定义分类标签

### 现象

用户创建了自定义分类（如"工作项目"），并在详情页将项目分配到该分类后，回到首页 — **卡片上完全看不到任何分类信息**。

### 根因分析

文件：`src/components/ProjectCard.tsx`

当前卡片展示的内容：
1. 项目类型图标（第 74 行）
2. 项目名称（第 82 行）
3. 路径（第 84 行）
4. Git 状态徽章（第 89 行）
5. README 摘要（第 90 行）
6. **技术栈标签**（第 93-97 行）← 只有自动检测的技术标签
7. 快捷操作按钮（第 100-152 行）

**缺少：自定义分类标签。**

`ProjectCard` 组件甚至没有接收 `customCategories` props，也不接收项目的 `customCategory` 字段。用户将项目加入自定义分类后，回到首页完全看不到任何反馈。

### UX 影响

- 用户无法一眼看出项目属于哪个自定义分类
- 侧边栏的分类筛选（已显示各分类数量）与卡片信息脱节
- 用户可能怀疑"我到底有没有成功把项目加进去？"

### 修复方案

**给 ProjectCard 增加自定义分类标签**，显示在技术栈标签旁边或上方。

需要传入的 props：
```typescript
interface ProjectCardProps {
  // ... 现有 props
  customCategories: CategoryDefinition[]   // 新增：用于查找分类名称和颜色
}
```

显示逻辑：
```tsx
// 在 ProjectCard 中
{customCategories && project.customCategory && (
  const cat = customCategories.find(c => c.id === project.customCategory)
  if (cat) {
    // 渲染带颜色的分类标签
    <span style={{ borderColor: cat.color, color: cat.color }}>
      <Tag size={12} /> {cat.name}
    </span>
  }
)}
```

**视觉设计建议**：
- 分类标签放在卡片顶部区域（名称下方 / 类型图标旁边），与技术标签区分开
- 使用分类的自定义颜色作为左边框或文字颜色
- 样式比技术标签更突出（因为这是用户手动管理的核心信息）
- 如果项目没有分类，不显示标签（保持简洁，不增加视觉噪音）

**位置选择**：

| 位置 | 优点 | 缺点 |
|------|------|------|
| 名称下方、路径上方 | 紧邻核心信息，最显眼 | 需要调整卡片布局 |
| 技术标签左侧 | 与其他标签排成一行 | 可能与技术标签混淆 |
| 类型图标右侧 | 与图标同行，利用右上角空间 | 空间有限，长名称可能溢出 |

**推荐：名称下方单独一行**，带彩色 Tag 图标 + 分类名称，让分类信息成为卡片的核心视觉元素。类似 GitHub project board 中 label 的展示方式。

## Issue 2: 详情面板分类展示方式严重误导用户

### 现象

打开项目详情面板，在"Category"区域 — **所有自定义分类都显示为可选按钮**，包括：

```
[ None ]  [ 🏷 工作项目 ]  [ 🏷 个人项目 ]  [ 🏷 开源贡献 ]
```

用户看到这个布局，直觉是：
- "这个项目已经被添加到了所有这些分类中"
- "这些按钮是在筛选什么？"
- "None 高亮但其他分类也都能点，什么意思？"

### 根因分析

文件：`src/components/ProjectDetail.tsx:80-112`

```tsx
{customCategories.length > 0 && (
  <DetailSection label={t('detail.category')}>
    <div className="flex flex-wrap gap-2">
      <button onClick={() => onCategoryChange(project.id, null)} ...>
        {t('detail.none')}
      </button>
      {customCategories.map((cat) => {
        const isActive = project.customCategory === cat.id
        return (
          <button onClick={() => onCategoryChange(project.id, cat.id)} ...>
            <Tag size={10} style={{ color: cat.color }} />
            {cat.name}
          </button>
        )
      })}
    </div>
  </DetailSection>
)}
```

问题分析：

1. **按钮群（Button Group）模式 = 多选暗示**：UI 中一行并排的按钮天然暗示"这些是可选项"，用户看到 3 个分类按钮 + None，大脑自动解读为"这些分类都关联到了这个项目"，就像标签云或 filter chips。

2. **区分度不足**：虽然 `isActive` 有不同的样式（`bg-stone-700` vs `bg-stone-800`），但在 `stone-950` 暗色背景下，这个差异非常微弱。用户需要仔细对比才能发现哪个是当前选中的。

3. **没有任何"选择器"的可发现性线索**：按钮组没有下拉箭头、没有"选择"文案、没有 radio button 样式。用户不知道这是在"选择分类"还是在"查看分类"。

4. **"None" 按钮的语义歧义**："None" 高亮时，用户会想："这表示项目没分类？还是表示我在看'未分类'这个筛选？"

### UX 影响

- **严重误导**：用户以为项目已经属于所有自定义分类
- **操作恐惧**：用户可能不敢点击其他分类按钮，怕"取消"当前分类
- **学习成本高**：需要通过试错才能理解这是单选而非多选

### 修复方案

**将按钮群改为下拉选择器（Dropdown Select）模式。**

下拉选择器是用户心智模型中"单选"的标准 UI 模式：

```
当前显示：
  Category
  ┌─────────────────────────────┐
  │ 🏷 工作项目              ▾  │  ← 点击展开下拉
  └─────────────────────────────┘

展开后：
  Category
  ┌─────────────────────────────┐
  │ 🏷 工作项目              ▴  │
  ├─────────────────────────────┤
  │   未分类                    │  ← hover 高亮
  │ ✓ 🏷 工作项目               │  ← 当前选中，打勾标记
  │   🏷 个人项目               │
  │   🏷 开源贡献               │
  └─────────────────────────────┘
```

关键设计要点：

1. **默认显示当前分类**（而非所有分类）：只渲染一个可点击的下拉按钮，展示当前生效的分类名称和颜色。未分类时显示"未分类"。

2. **下拉箭头（▾）作为 affordance**：明确告诉用户"这里可以展开选择"。

3. **选中项打勾标记（✓）**：展开后，当前选中的项前面有 checkmark，其余项没有 — 这是单选列表的通用模式，用户瞬间能理解。

4. **hover 效果**：鼠标悬停的项有背景色变化，进一步强化"可点击"的可发现性。

5. **点击外部关闭**：复用已有的 `onBlur` 失焦关闭逻辑（与 IDE 下拉菜单一致）。

实现要点：

```tsx
// ProjectDetail.tsx 改造思路
const [showCategoryMenu, setShowCategoryMenu] = useState(false)

const currentCategory = customCategories.find(c => c.id === project.customCategory)

<div className="relative" tabIndex={0} onBlur={...}>
  <button onClick={() => setShowCategoryMenu(!showCategoryMenu)}>
    {currentCategory ? (
      <><Tag color={currentCategory.color} /> {currentCategory.name}</>
    ) : (
      t('detail.uncategorized')
    )}
    <ChevronDown />
  </button>
  {showCategoryMenu && (
    <div className="absolute ...">
      <button onClick={() => { onCategoryChange(project.id, null); setShowCategoryMenu(false) }}>
        {!project.customCategory && <Check />}
        {t('detail.uncategorized')}
      </button>
      {customCategories.map(cat => (
        <button onClick={() => { onCategoryChange(project.id, cat.id); setShowCategoryMenu(false) }}>
          {project.customCategory === cat.id && <Check />}
          <Tag color={cat.color} /> {cat.name}
        </button>
      ))}
    </div>
  )}
</div>
```

**为什么不把分类选择放在卡片上（inline edit）？**
- 卡片空间有限，交互复杂时容易误操作
- 分类分配是低频操作，不需要在卡片上暴露完整选择器
- 卡片只需要"显示"分类，详情面板负责"修改"分类

## Issue 3: 分类分配操作不可发现

### 现象

用户创建了自定义分类后，**不知道去哪里、怎样把项目添加到分类中**。

正确的操作路径是：
```
首页 → 点击项目卡片 → 详情面板 → Category 区域 → 点击分类按钮
```

但这个路径：
1. **入口隐藏太深**：需要 3 步才能到达操作点
2. **详情面板无引导**：打开详情面板后，Category 区域没有任何操作提示
3. **分类创建和分类分配脱节**：在设置中创建了分类，但首页完全没有任何线索告诉你"现在可以去给项目打标签了"

### UX 影响

- 用户创建分类后面临"然后呢？"的困惑
- 功能存在但用户以为不存在 → 功能失效

### 修复方案

**多层次可发现性提升：**

**A. 卡片上的视觉线索（配合 Issue #1 修复后）：**

修复 Issue #1 后，已分类的项目会在卡片上显示分类标签。这本身就是一种"教育" — 用户看到"这个项目有分类"，就会好奇"怎么给其他项目也加分类？"

**B. 未分类项目的 subtle affordance：**

对未分类项目，在卡片上可以加一个极 subtle 的 hover 提示（可选，避免过度设计）：
- 不要加明显的"未分类"标记（会造成视觉噪音）
- 如果要做，可以在 hover 时在 More 按钮区域显示一个小提示

**C. 详情面板的引导文案（推荐）：**

当项目未分类时，Category 下拉按钮显示"未分类"，并可用更 subtle 的样式（如虚线边框）暗示"这里可以选"：

```
┌─────────────────────────────┐
│ ＋ 分配分类              ▾  │  ← 虚线边框，引导操作
└─────────────────────────────┘
```

当项目已分类时，显示明确的分类型标签，让用户知道"已分类，可以改"：

```
┌─────────────────────────────┐
│ 🏷 工作项目              ▾  │  ← 实线边框，常规样式
└─────────────────────────────┘
```

**D. 侧边栏的隐式引导：**

侧边栏已经显示了分类筛选和各类的项目数。当用户创建第一个分类后，侧边栏出现分类区域，自然会引导用户"为什么这里有个分类筛选？点击后会显示什么？"
